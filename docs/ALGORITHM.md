# Алгоритм

## 1. Входные данные

В production-версии каждый LMI Gocator передаёт последовательность поперечных
профилей. Профиль содержит координаты `x`, `z`, номер импульса энкодера и
интенсивность отражения. Координата `y` вычисляется по энкодеру.

В демо реальные профили заменены двумя синтетическими ракурсами облака.
Генератор создаёт поверхности параллелепипеда, оставляет видимые для каждого
ракурса грани, добавляет гауссов шум, точки ленты и одиночные выбросы. Это не
физическая модель профилометра: лазерные линии, энкодер, временная развёртка и
сложные окклюзии не моделируются.

## 2. Приведение к общей системе координат

Для реальной установки каждому сенсору нужна матрица `T_sensor_to_belt` размером
4×4. Её получают по общей калибровочной детали. Демонстрационные точки уже
находятся в системе конвейера, поэтому этот шаг показан логически, но матрица
равна единичной.

## 3. Удаление ленты

Плоскость ленты принимается за `z = 0`. Точки с
`z <= belt_z + belt_tolerance` удаляются. В production плоскость лучше заново
оценивать по пустым профилям перед сменой.

## 4. Удаление выбросов

Пространство делится на кубические ячейки со стороной `radius_mm`. Для каждой
точки просматриваются 27 соседних ячеек. Если внутри радиуса нет заданного
числа соседей, точка считается одиночным выбросом.

## 5. Выпуклая оболочка

Для проекции точек на XY строится выпуклая оболочка алгоритмом монотонной цепи.
Сложность после сортировки — `O(N log N)`. Внутренние точки дальше не нужны,
потому что они не могут изменить внешний прямоугольник.

## 6. Минимальный прямоугольник

Для каждого ребра оболочки строятся две оси:

- `u` параллельна ребру;
- `v` перпендикулярна ребру.

Точки проецируются на `u` и `v`. Разности максимальной и минимальной проекций
дают две стороны прямоугольника. Выбирается вариант с минимальной площадью.
Это вариант метода вращающихся калиперов.

Высота считается от известной плоскости ленты до максимального `z`.

## Ограничение базовой версии

ТЗ требует минимальный параллелепипед в полной 3D-ориентации. Базовая версия
решает 2.5D-задачу: обрабатывает поворот вокруг Z, но не моделирует наклоны
вокруг X и Y. Для произвольной ориентации по трём осям следует использовать
3D-выпуклую оболочку и
`Open3D MINIMAL_JYLANKI`, как описано в отчёте.

Передача по HTTP в WMS в базовое демо не входит. Её заменяет запись результата
в `result.json`.

## Проверка на наборах данных

Команда `ozon-dim-benchmark` запускает девять воспроизводимых сценариев из
`datasets/scenarios.json`. Наборы различаются размерами, поворотом, уровнем
шума, долей пропусков и доступностью второго сенсора.

В текущей серии все семь геометрических сценариев проходят заданный допуск.
Максимальная ошибка равна 5,29 мм при допустимых 6,5 мм в сценарии с повышенным
шумом. В двух сценариях с недостаточными данными quality gate возвращает
`REJECT`, поэтому недостоверные размеры не публикуются.

Команда `ozon-dim-generate-datasets` создаёт исходные данные этих сценариев в
отдельных каталогах. Для каждого набора сохраняются `sensor_1.csv`,
`sensor_2.csv` (если второй ракурс доступен) и `metadata.json`. В CSV находятся
координаты `x_mm`, `y_mm`, `z_mm`, а фиксированный `seed` делает генерацию
воспроизводимой.
